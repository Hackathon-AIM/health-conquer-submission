# 성능 개선 기록

## 무엇을 개선했는가

대회 제공 모델 **`Lunit/L2-preview`의 가중치를 바꾸는 학습이 아니라, 모델 호출 전후의 추론 파이프라인**을 개선했습니다. 답변 지시, 문맥 전달, 검색 적용 범위, 시간·출력 예산, 출력 검증이 대상입니다.

이 문서는 README 개편 직전 코드 [`f7cb887`](https://github.com/Hackathon-AIM/health-conquer-submission/tree/f7cb887)와 개발 이력을 기준으로 작성했습니다.

위 개발 수치는 당시 코드·커밋에 남은 기록입니다. 동일 데이터·채점기·반복 횟수·서버 상태를 검증할 원본 결과가 없어 **통제된 A/B 결과나 공식 최종 점수로 간주하지 않습니다.** `38.34 → 50.03 → 51.16`을 각 기능의 인과적 개선 폭으로 계산하지 않습니다.

상장과 기사에는 최종 점수 숫자나 특정 프론티어 모델별 비교표가 없습니다. 따라서 특정 모델을 몇 점 앞섰다는 주장은 하지 않습니다.

## 1. 직접 생성 경로를 기본으로 채택

초기 설계에는 분류, 검색, 생성, 안전 게이트, 비평 등이 포함됐습니다. 현재 Docker 진입점은 `app.py`이고 기본 설정은 `PIPELINE=raw`입니다.

- 대화 이력을 L2에 전달해 직접 생성합니다.
- 매 질문마다 수행하던 분류·광범위 검색을 기본 경로에서 제외합니다.
- 필요한 공식 데이터만 좁게 조회합니다.
- `PIPELINE=harness`로 검색 중심 경로를 비교할 수 있습니다.

개발 주석은 직접 생성 경로에서 더 높은 실측 점수를 얻었다고 설명합니다. 다만 호출 수 감소와 점수 변화의 인과관계를 분리한 원본 실험 자료는 공개 저장소에 없습니다.

**코드:** [`app.py`의 `_draft_raw`, `_draft_harness`, `generate_reply`](../app.py)

## 2. 답변 커버리지와 멀티턴 문맥 보강

`ANSWER_INSTRUCTION`을 최신 사용자 메시지에 붙여 다음 행동을 요청합니다.

- 사용자가 물은 각 항목에 답하기
- 필요한 주의 신호를 설명하기
- 검사 결과·약물 목록·측정값 등 사용자가 제공할 수 있는 정보를 요청하기
- 결정적인 정보가 부족하면 한 가지를 확인하되, 현재 정보로 답할 수 있는 범위는 먼저 답하기

이전 대화는 유지합니다. 한국어 공식 자료 조회에서 “그 약”, “그 코드”와 같은 후속 질문은 최근 사용자 문맥에 유일한 대상이 있을 때 해소합니다. 모호하면 지정 도구 조회를 수행하지 않습니다.

[`5da35d4`](https://github.com/Hackathon-AIM/health-conquer-submission/commit/5da35d4fd6856213541be28ab738f333644b675f)의 개발 기록에는 멀티턴 성능 저하를 관찰한 뒤 문구를 보완했다는 설명이 있습니다. **해당 추가 문구 자체의 점수 효과는 미검증**이라고 명시되어 있어, 이미 확인된 개선량처럼 표현하지 않습니다.

**코드:** [`app.py`](../app.py)의 `_with_answer_instruction`, `_resolve_deictic_lookup_text`<br>
**이력:** [`52e79c8`](https://github.com/Hackathon-AIM/health-conquer-submission/commit/52e79c8f5e2cb080466f9a299ee05b0afd9d0f69), [`45374b7`](https://github.com/Hackathon-AIM/health-conquer-submission/commit/45374b7)

## 3. 공식 데이터가 필요한 경우만 MCP 사용

기본 경로에서 한국어로 명확히 요청한 약가, 식약처 허가·적응증, 성분별 제품, KCD 코드·명칭, HIRA 코드 확인 등을 해당 MCP 도구에 매핑합니다.

- 도구 선택은 규칙 기반입니다.
- 빈 결과나 오류에는 제한된 재시도를 적용합니다.
- 확보한 결과를 최대 6,000자로 제한해 사용자 턴에 연결합니다.
- 결과에 없는 수치·코드·허가 정보를 추측하지 않도록 지시합니다.
- 근거 확보에 실패하면 기존 직접 생성 경로를 유지합니다.

범용 RAG를 모든 질문에 붙이는 것과 다릅니다. 선택적 조회의 코드와 커밋은 있으나, 도구별 공식 점수 향상량을 보여주는 결과 파일은 첨부되어 있지 않습니다.

**코드:** [`app.py`](../app.py)의 `_select_frontier_lookup`, `_with_selective_frontier_evidence`<br>
**이력:** [`7dc8c8d`](https://github.com/Hackathon-AIM/health-conquer-submission/commit/7dc8c8d3141d40ff53bbe3d4be4570c8fdbc8c6e)

## 4. 토큰과 시간 예산으로 응답 완결성 확보

기본 최대 출력은 **6,144토큰**입니다. 직접 생성에서는 thinking을 사용하되 남은 시간이 부족하면 끄며, 잘림·빈 응답·호출 실패에는 non-thinking 답변 또는 짧은 복구 답변을 시도합니다.

`app.py`에 기록된 12문항 개발 관찰에서는 2,048토큰 설정에서 1건의 잘림이 있었고, 4,096·6,144·8,192 설정에서는 잘림이 관찰되지 않았습니다. 이는 **소규모 개발 기록**이며 전체 평가셋에 대한 실패율 보장이 아닙니다.

시간 관리에는 재시도·백오프를 포함하는 호출 예산과 동시 요청 제한이 포함됩니다. `REQUEST_BUDGET_S=40` 외에 답변·복구 호출 예산이 별도로 존재하므로 “모든 응답이 40초 이내”라고 주장하지 않습니다. 모든 복구가 실패하면 빈 응답이 반환될 수 있습니다.

**코드:** [`app.py`](../app.py), [`budget.py`](../budget.py)

## 5. 필요한 출력 검증만 수행하고 긴 답변 보존

기본 `REVIEW_MODE=suspect`는 잘림·반복 등 결함 신호가 있을 때만 추가 모델 호출을 수행합니다. 검증 실패 시에는 가능한 초안을 보존합니다.

`review.py`의 개발 기록에는 기존 6,000자 상한이 80개 로컬 응답 중 23개를 잘랐고, 해당 23개에 대한 paired grading에서 답변 보존이 **13승·7패·3무**였다고 적혀 있습니다. 이 기록에 따라 기본 상한은 12,000자로 확대됐습니다.

이 수치는 **코드 주석에 남은 로컬 비교**입니다. 원본 채점 결과가 없으므로 공식 벤치마크 개선량으로 바꾸어 표기하지 않습니다.

**코드:** [`review.py`](../review.py)<br>
**이력:** [`ef3609d`](https://github.com/Hackathon-AIM/health-conquer-submission/commit/ef3609d26b1c8e63e8a6e7a62be223e77467c8ab)

## 재현과 증빙 범위

- **재현 가능한 범위:** 코드 경로, 설정 기본값, 로컬 단위 테스트 및 mock 감사.
- **확인된 외부 성과:** 상장·수상 기사에 기록된 HealthBench 최고점과 벤치마크 상.
- **추가 자료가 필요한 범위:** 최종 제출 SHA에 대응하는 공식 점수, 평가셋·채점기 설정, 변경별 원본 A/B 결과.
- **범위 밖:** 모델 가중치 학습 성과, 특정 프론티어 모델 대비 우위 수치, 실제 환자 대상 임상 효과.
