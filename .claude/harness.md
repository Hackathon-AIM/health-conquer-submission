# med_ai 에이전트 팀 구성

## 왜 에이전트 팀인가 (서브 에이전트가 아니라)

세 가지 질문으로 판단한다.

1. **결과물을 다음 단계에 넘기는가?** → 넘긴다.
   analyst 의 우선순위 표가 있어야 builder 가 뭘 고칠지 정하고,
   builder 의 변경이 있어야 qa 가 A/B 를 잰다.
2. **동시에 다른 관점이 필요한가?** → 부분적으로.
   안전 회귀와 점수 향상은 서로 다른 판단 기준이라 같은 에이전트가 겸하면
   "점수 올랐으니 됐다" 로 안전을 넘긴다.
3. **한 번만 하면 끝인가?** → 아니다. 해커톤 내내 도는 루프다.

→ **에이전트 팀**. 단발성 작업(함수 하나 리팩토링, 에러 번역)은 서브 에이전트로 충분하다.

## 선택한 패턴: 생성–검증 + 파이프라인

```
analyst  ──(우선순위 표)──▶  builder  ──(변경 + 스위치)──▶  qa
   ▲                                                        │
   └──────────────  되돌림 판정 / 다음 finding  ◀────────────┘
```

- **파이프라인** 성질: 앞 단계 결과 없이는 다음 단계가 불가능하다.
  finding 없이 고칠 수 없고, 변경 없이 잴 수 없다.
- **생성–검증** 성질: builder 가 만들고 qa 가 별도 기준으로 검수한다.
  한 에이전트가 자기 변경을 자기가 검수하면 기준이 느슨해진다.

**팬아웃을 안 쓰는 이유**: 우리 병목은 관점의 다양성이 아니라
"이번 변경이 점수를 올렸는가" 라는 단일 질문이다. 병렬로 여러 관점을 붙이면
어느 변경이 효과를 냈는지 분리가 안 된다.

## 역할 경계 — 이걸 지켜야 팀이 의미가 있다

| 에이전트 | 하는 일 | **절대 안 하는 일** |
|---|---|---|
| analyst | 원인 특정, 우선순위 | 코드 수정 |
| builder | 최소 diff 구현 | 자기 변경 채택 결정 |
| qa | A/B 측정, 되돌림 판정 | 원인 분석 (analyst 에게 되돌림) |

qa 만 "되돌려라" 라고 말할 수 있다.

## 트리거 프롬프트

**한 사이클 전체**
```
CoEval 결과가 나왔어. analyst 로 실패를 군집화해서 우선순위 표 만들고,
1순위 하나만 builder 로 고치고, qa 로 A/B 재서 채택할지 판정해줘.
finding 하나만. 두 개 같이 고치지 마.
```

**분석만**
```
analyst 로 logs/ 와 최근 CoEval 결과 읽고 우선순위 표만 뽑아줘. 코드는 건드리지 마.
```

**검증만**
```
qa 로 골든 시나리오 5종 + make test + make audit 돌리고 판정문 내줘.
```

**기준선 점검 (하루 한 번은 돈다)**
```
qa 로 ab-baseline 돌려서 우리 파이프라인(l2_live)이 기준선(l2_raw)을 넘는지 확인해줘.
못 넘으면 어느 레이어가 마이너스인지 layers 스위치 하나씩 꺼가며 찾아줘.
```

**제출 게이트 (커밋 전마다)**
```
spec 스킬로 제출 규격 점검해줘. 포트·브랜치·빌드 시간·엔드포인트 전부.
```

## 왜 `spec` 스킬이 따로 있는가

analyst·builder·qa 는 전부 **"우리 코드가 어떤가"** 를 본다. 아무도
**"대회가 뭘 요구했는가"** 를 보지 않는다. 그 결과 두 종류의 사고가 난다:

1. **규격 위반 = 0점.** 점수를 아무리 올려도 포트·브랜치·빌드 시간을 어기면 전부 무효다.
2. **사양을 기억으로 답하기.** CoEval Hydra 경로를 `client.api_base` 로 알고 있다가
   `Key 'api_base' is not in struct` 에서 반나절을 태우는 식이다.

`spec` 은 에이전트가 아니라 스킬이다 — 판단이 아니라 **조회**이기 때문이다.
누가 부르든 답이 같아야 하고, 답의 출처는 `docs/spec.md` 한 곳이어야 한다.

`references/` 는 Progressive Disclosure 다. SKILL.md 는 짧게 유지하고,
표와 사례는 필요할 때만 읽히도록 분리한다. 컨텍스트가 절약되는 만큼
실험 회전 수가 늘어난다.

## 이 팀이 못 하는 것

- **점수를 대신 올려주지 않는다.** 루프의 회전 수를 늘려줄 뿐이다.
- **FM 엔드포인트가 없으면 절반은 무의미하다.** `configs/openai.yaml` 로 도는 숫자는
  파이프가 뚫렸다는 증거일 뿐 실력의 증거가 아니다.
- **판단을 대신하지 않는다.** 특히 "파이프라인을 꺼야 하는가" 는 사람이 정한다.
